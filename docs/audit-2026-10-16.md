# pleamar audit, 2026-10-16

## scope

reviewed the running material shell, its Luau logic and scene parts, Python and C helpers, rice scripts, IPC wrappers, systemd units, Hyprland integration, and the existing runtime text patch. runtime source review covered the local patch and relevant input, logic scheduling, clock and IPC paths. this was not a line-by-line audit of the entire upstream Rust engine or its dependencies.

the session used one eDP-1 output at 1920×1080, scale 1, approximately 60 Hz, with Intel ADL-N graphics. the bar reserved 42 pixels. the running runtime was Pleamar 0.4.2 with the existing text patch. no runtime rebuild or upstream update was needed.

## fixed

### application search latency

before this change, each edit waited 60 ms, started Python, enumerated desktop entries through Gio, sorted them and searched their names and descriptions. reopening also discarded the application list.

`desktop.py watch` now keeps the catalog and Unicode casefolded search text in memory. the shell sends queries over one process's stdin, rejects obsolete response generations and reuses the full catalog when reopening. Gio monitors application changes. hidden-state writes use the same request stream, preventing races between saving the list and reading it for a search. the existing worker supervisor restarts the process after two seconds.

measurements on this session:

| measurement | result |
| --- | --- |
| previous helper, 20 process invocations | median 138.04 ms, maximum 144.99 ms |
| previous debounce, additional to helper cost | 60 ms |
| final worker, 50 query round trips | median 0.097 ms, maximum 1.223 ms |
| final live shell, 24 query/count checks through IPC | median 28.53 ms, maximum 62.56 ms |

the live measurement includes two IPC command invocations and waiting for the scene's result count. it does not measure physical keyboard-to-display latency. there was no equivalent live baseline; do not interpret the helper speedup as the same speedup for the entire interface. two successive queries with the same result count can satisfy a count check before the new content arrives; separate content and correctness checks covered this case.

### hidden-state validation

the reader now tolerates valid JSON with an unexpected schema and skips non-string IDs. invalid worker requests return an error without terminating the process. state writes remain atomic.

## follow-up fixes

| finding | change | verification |
| --- | --- | --- |
| animation frame pacing | the service sets `PLEAMAR_FIFO=1`; the Hyprland integration disables the compositor's additional fade for Pleamar surfaces. shell springs, tilt and content transitions remain. | comparable 12-cycle probe runs reduced late frames from 29.1% to 9.8%; see measurements below. |
| terminal desktop entry field codes | the launcher expands `%c`, `%k`, `%i` and `%%`, removes unused file and deprecated codes, rejects unknown codes, and honors `Path`. arguments go to kitty without a shell. | isolated executable fixtures verify argv, working directory, literal percent handling, single expansion and rejection of invalid codes. rules follow the [desktop entry specification](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html). |
| queued Wi-Fi commands | the GLib callback reads fd bytes and drains complete JSON lines, retaining partial UTF-8 for the next read. malformed commands do not discard following commands. | batched input, split Cyrillic, malformed JSON and EOF tests pass without a live network. |
| Bluetooth errors affecting Wi-Fi | synchronous and asynchronous Bluetooth failures use Bluetooth handling. errors clear pairing state and reject pending agent replies without changing Wi-Fi state. PIN/passkey validation rejects invalid input once; disconnected replies do not interrupt cleanup. | isolated callback tests cover successful replies, invalid values, rejection, disconnected callbacks and both directions of error isolation. |
| repeated thumbnail work | one persistent gallery worker owns one converter. logic reuses completed preview paths for selection changes, replaces the pending window, cancels obsolete conversion and retries failures on refresh. | tests verify cancellation, latest-window coalescing, reuse, temporary-file cleanup and converter termination when its worker receives SIGTERM or SIGKILL. live previews and scrolling were inspected. |
| unsupervised session helpers | `rice-session.target` starts the packaged hyprpaper, hypridle and swaync services with restart drop-ins, plus OSD and clipboard units. the startup script imports environment and starts the target. | all five helpers recovered after SIGTERM; repeating the startup script preserved process IDs. |

### animation measurements

the probe alternated launcher and control-center panels over 12 cycles, waiting 650 ms after opening and 550 ms after closing. these are short measurements on a desktop in use, not an isolated GPU benchmark.

| metric | previous mailbox configuration | final FIFO configuration and native shell animation |
| --- | --- | --- |
| measured frames | 436 | 562 |
| median frame | 21.8 ms | 17.5 ms |
| p95 frame | 39.1 ms | 26.8 ms |
| p99 frame | 44.1 ms | 28.0 ms |
| maximum frame | 47.7 ms | 33.9 ms |
| frames over 1.5 display periods | 127 (29.1%) | 55 (9.8%) |
| frames over 2.5 display periods | 17 | 0 |
| reported card memory | 44 MB | 35 MB |

FIFO alone produced 9.1% late frames in an earlier run. disabling the additional compositor fade produced 8.3% in another run and 9.8% in the final run. the small difference between FIFO variants is not enough to attribute a precise performance gain to the layer rule. disabling the duplicate fade keeps panel timing under the shell's control.

the change reduces stalls but does not guarantee a 16.7 ms frame budget. the final probe attributes most remaining late-frame time to submitting/painting the frame. further gains would require profiling the renderer and driver. at this stage the runtime binary and its existing text patch remained unchanged. the subsequent [renderer study](optimization-2026-10-16.md) records the installed fill optimization and final measurements.

## validation

- scene syntax passed `pleamar --check`.
- Python checks passed `ruff check --select E9,F63,F7,F82` for shell and rice helpers.
- shell wrappers, startup and the idle helper build script passed `shellcheck -S warning`.
- shell and asset units passed `systemd-analyze --user verify`; no failed user units were present.
- fourteen isolated automated tests passed across search, terminal launch, connectivity queues and errors, and gallery scheduling and cleanup.
- 40 worker responses matched the previous list implementation, including Cyrillic and uppercase queries.
- live checks passed for hide/unhide, state persistence, rapid query replacement, selection and scrolling to the last item, reopening and recovery after terminating the desktop worker. hidden-state content was restored after the test.
- all eight panel commands opened and closed their corresponding surfaces. the launcher screenshot was inspected for layout, icons and text.
- a service restart loaded the final helper; old helper processes did not survive it. the search worker recovered after an intentional SIGTERM.
- the existing runtime text patch matched the checkout's changes; textual diff differences were context width only. the patch and binary were preserved.

## limits

no live Wi-Fi reconnect, password failure, Bluetooth pairing, audio device switch, suspend, lock, reboot or logout test was performed. no external display was attached. opening the connectivity panels requested the shell's normal Wi-Fi scan. panel smoke checks establish that the panels render and close, not that every hardware action succeeds. real tray applications and full application launch semantics need separate checks.

backups of the original logic and desktop helper are in `~/.local/state/pleamar/audit-2026-10-16/`. only the changed shell files were copied to the source checkout; the repository was not published. the owning `~/.codex/instructions/system/software/pleamar.md` reference now routes helper startup through `rice-session.target`. implementation, service and protocol details live in the shell and rice readmes. follow-up backups and raw performance reports are in `~/.local/state/pleamar/fixes-2026-10-16/`. the source checkout also includes the existing live tooltip and keyboard fixes, which had not previously reached that checkout.
